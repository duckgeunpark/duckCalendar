# duckCalendar Database Guide (for AI / external tools)

`duckCalendar.db` in this folder is the **single source of truth (SQLite)** for the duckCalendar app.
This document describes the schema and rules so an AI tool or script can **read, create, and edit events directly**.

> ⚠️ It is safe to modify the DB while the app is running (WAL mode). However, the UI does not refresh
> instantly — switch between month/week/day views or restart the app to reload.
>
> This file is regenerated by the app on every launch, so manual edits will be overwritten.

---

## 1. File / Connection

- Path: `%APPDATA%\com.duckcalendar.app\duckCalendar.db`
- Engine: **SQLite 3** (`PRAGMA journal_mode=WAL`, `PRAGMA foreign_keys=ON`)
- The companion `-wal` and `-shm` files are normal WAL sidecar files.

Connect with `sqlite3 duckCalendar.db`, Python `sqlite3`, Node `better-sqlite3`, etc.

## 2. Main table: `events`

| Column | Type | Description |
|---|---|---|
| `event_id` | TEXT PK | Unique ID. Use a **UUID v4** (lowercase, hyphenated). e.g. `a1b2c3d4-...` |
| `calendar_id` | TEXT FK | Owning calendar. Default **`local-default`** (always exists, visible). References `calendars.calendar_id`, ON DELETE CASCADE |
| `title` | TEXT | Title (required) |
| `description` | TEXT | Description. Default `''` |
| `location` | TEXT | Location. Default `''` |
| `start_at` | TEXT | **Start**. Format depends on `all_day` (see §3) |
| `end_at` | TEXT | **End (EXCLUSIVE)**. See §3 |
| `all_day` | INTEGER | `1` for all-day, `0` for timed |
| `color` | TEXT NULL | Event color (hex, e.g. `#ff8800`). NULL = use theme accent |
| `source` | TEXT | `'local'` or `'google'`. Use `'local'` for hand-created rows |
| `google_event_id` | TEXT NULL | For Google sync. NULL for local rows |
| `google_calendar_id` | TEXT NULL | same |
| `etag` | TEXT NULL | same |
| `sync_enabled` | INTEGER | Whether to sync. Default `0` |
| `sync_status` | TEXT | `local` \| `pending` \| `synced` \| `failed`. Use `'local'` for local rows |
| `last_error` | TEXT NULL | Sync error message |
| `created_at` | TEXT | Creation time (RFC3339 UTC). e.g. `2026-06-15T01:48:19+00:00` |
| `updated_at` | TEXT | Last update time (RFC3339 UTC) |

Indexes: `idx_events_start(start_at)`, `idx_events_calendar(calendar_id)`

## 3. Time format rules (most important)

`start_at` / `end_at` use a different format depending on `all_day`.

### Timed events (`all_day = 0`)
- **RFC3339 string with the LOCAL timezone offset.**
  - Example (Korea, UTC+9): `2026-06-15T09:00:00+09:00` to `2026-06-15T10:00:00+09:00`
- The app computes on-screen position **assuming this offset matches the local timezone.**
  → Always write the **user's local offset**. Writing `...Z` (UTC) shifts the event by the offset amount.
- `end_at` must be after `start_at`.

### All-day events (`all_day = 1`)
- **`YYYY-MM-DD`** (date only).
- `end_at` is **EXCLUSIVE** — the *day after the last day*.
  - One day (Jun 15): `start_at='2026-06-15'`, `end_at='2026-06-16'`
  - Three days (Jun 15–17): `start_at='2026-06-15'`, `end_at='2026-06-18'`

### Range-overlap query (how the app fetches)
Events overlapping a half-open range `[range_start, range_end)`:
```sql
WHERE start_at < :range_end AND end_at > :range_start
```
This works via lexical (string) comparison for both `YYYY-MM-DD` and RFC3339 values.

## 4. Other tables

### `calendars`
| Column | Description |
|---|---|
| `calendar_id` PK | Default local calendar = `local-default` |
| `name` | Name (default local: `내 캘린더`) |
| `color` | Default `#4285F4` |
| `source` | `'local'` \| `'google'` |
| `google_calendar_id` | NULL allowed (for sync) |
| `visible` | Must be `1` for its events to appear in the app |
| `is_primary` | Marks the primary calendar |
| `sync_token` | For sync |

> The app only queries events from calendars where `visible = 1`. New events should normally go into `local-default`.

### `app_settings` (key-value)
| Column | Description |
|---|---|
| `setting_key` PK | e.g. `theme`, `lang`, `window_mode`, `opacity`, `ui_scale`, `win_x/y/w/h`, `google_client_id` |
| `setting_value` | string value |

### Legacy (backward-compat only — usually leave alone)
- `memos`, `google_sync_map`: old memo data. Migrated into `events` once, only when `events` is empty and `memos` has rows.

## 5. Example SQL

### Create a timed event (Jun 15, 09:00–10:00, Korea time)
```sql
INSERT INTO events
  (event_id, calendar_id, title, description, location,
   start_at, end_at, all_day, color, source, sync_enabled, sync_status, created_at, updated_at)
VALUES
  ('<uuid-v4>', 'local-default', 'Team meeting', 'Weekly standup', '',
   '2026-06-15T09:00:00+09:00', '2026-06-15T10:00:00+09:00',
   0, NULL, 'local', 0, 'local',
   strftime('%Y-%m-%dT%H:%M:%S+00:00','now'), strftime('%Y-%m-%dT%H:%M:%S+00:00','now'));
```
> Tip: `lower(hex(randomblob(16)))` yields a 32-char hex (not a canonical UUID). Generate a real
> UUID v4 (`8-4-4-4-12`) externally if you want the standard format. (The app does not enforce it.)

### Create an all-day event (Jun 20, one day)
```sql
INSERT INTO events
  (event_id, calendar_id, title, start_at, end_at, all_day, source, sync_enabled, sync_status, created_at, updated_at)
VALUES
  ('<uuid-v4>', 'local-default', 'Vacation', '2026-06-20', '2026-06-21',
   1, 'local', 0, 'local',
   strftime('%Y-%m-%dT%H:%M:%S+00:00','now'), strftime('%Y-%m-%dT%H:%M:%S+00:00','now'));
```

### Query events for a month (2026-06)
```sql
SELECT event_id, title, start_at, end_at, all_day
FROM events
WHERE start_at < '2026-07-01' AND end_at > '2026-06-01'
ORDER BY all_day DESC, start_at;
```

### Update / delete
```sql
UPDATE events SET title = :title, start_at = :start, end_at = :end,
       updated_at = strftime('%Y-%m-%dT%H:%M:%S+00:00','now')
WHERE event_id = :id;

DELETE FROM events WHERE event_id = :id;
```

## 6. Checklist when creating an event

1. `calendar_id` = a visible calendar (`local-default`).
2. Match `start_at`/`end_at` **format** to `all_day` (timed = RFC3339 + local offset; all-day = `YYYY-MM-DD` with `end_at` = next day).
3. `source='local'`, `sync_status='local'`, `sync_enabled=0`.
4. Prefer `''` (empty string) over NULL for `description`/`location`.
5. Set `created_at`/`updated_at` (RFC3339).
6. The app reflects changes on view switch / restart.
