# 데스크톱 캘린더 위젯 설계서 초안

## 개요
본 문서는 Windows 데스크톱 환경에서 동작하는 경량 캘린더 위젯 애플리케이션의 1차 설계 초안을 정의한다. 애플리케이션은 바탕화면에서 상시 확인 가능한 월간 달력 UI를 제공하며, 사용자는 날짜별 메모를 로컬 PC에 저장할 수 있어야 한다. 앱의 기본 동작은 완전한 로컬 우선(Local-first) 구조를 따른다[cite:69][cite:80].

애플리케이션은 시스템 시간을 기준으로 현재 연월의 달력을 자동 표시해야 하며, 사용자가 날짜를 선택해 메모를 기록·조회·수정·삭제할 수 있어야 한다. 또한 저장된 데이터를 외부로 추출할 수 있어야 하며, 외부 캘린더와의 호환성을 고려해 표준 일정 포맷으로 변환 가능한 구조를 가져야 한다[cite:38][cite:44].

Google Calendar 연동은 선택 기능으로 제공한다. 사용자는 구글 계정 로그인과 권한 동의를 통해 연동을 활성화할 수 있으며, 이를 사용하지 않아도 앱의 핵심 기능은 모두 동작해야 한다. Google Calendar 접근에는 OAuth 2.0 기반 권한 승인과 Calendar scope 설정이 필요하다[cite:58][cite:54].

## 기능 요구사항

### 1. 달력 표시
- 애플리케이션은 운영체제의 시스템 시간을 기준으로 현재 연도와 월을 계산하여 해당 월의 달력을 기본 화면에 표시해야 한다.
- 사용자는 이전 달, 다음 달로 이동할 수 있어야 한다.
- 사용자가 특정 날짜를 선택하면 해당 날짜의 메모 목록과 상세 내용을 확인할 수 있어야 한다.
- 메모가 존재하는 날짜는 시각적으로 구분되어야 한다.

### 2. 날짜별 메모 관리
- 사용자는 특정 날짜에 하나 이상의 메모를 저장할 수 있어야 한다.
- 각 메모는 최소한 다음 정보를 포함해야 한다.
  - 메모 식별자
  - 대상 날짜
  - 제목
  - 본문 내용
  - 생성 시각
  - 수정 시각
- 사용자는 메모를 생성, 조회, 수정, 삭제할 수 있어야 한다.
- 메모는 기본적으로 로컬 저장소에 즉시 반영되어야 한다.

### 3. 데이터 추출
- 사용자는 특정 날짜, 특정 월, 또는 전체 데이터를 추출할 수 있어야 한다.
- 추출 포맷은 최소 JSON을 지원해야 하며, 확장 포맷으로 CSV와 ICS를 고려한다.
- 외부 캘린더 연동을 위한 데이터는 이벤트 구조로 변환 가능해야 한다. iCalendar는 캘린더 및 일정 교환을 위한 표준 데이터 형식이며, 이벤트는 `VEVENT` 컴포넌트로 표현된다[cite:38][cite:44].

### 4. Google Calendar 선택 연동
- 사용자는 앱 사용 중 별도 API 신청이나 키 입력 없이 Google Calendar 연동을 선택적으로 활성화할 수 있어야 한다.
- 연동 시 사용자는 브라우저 기반 로그인 및 권한 동의 절차를 진행해야 한다.
- 권한 승인 후 앱은 사용자의 Google Calendar에 이벤트를 생성하거나 수정할 수 있어야 한다. Google Calendar API는 OAuth 기반으로 동작하며, 필요한 범위의 scope를 선언해 접근 권한을 받아야 한다[cite:58][cite:54].
- 사용자가 연동을 활성화하지 않은 경우에도 로컬 메모 기능은 동일하게 동작해야 한다.

### 5. 동기화 대상 선택
- 모든 메모가 자동으로 Google Calendar에 반영되면 안 되며, 사용자가 반영 대상을 선택할 수 있어야 한다.
- 로컬 메모와 외부 캘린더 이벤트는 개념적으로 구분되어야 한다.
- 메모 중 일정성 데이터만 외부 이벤트로 변환 가능해야 한다.

## 비기능 요구사항

### 1. 경량성
- 애플리케이션은 데스크톱 위젯 용도에 맞게 메모리 사용량과 CPU 점유율이 낮아야 한다.
- 상시 실행을 전제로 하므로 빠른 시작 속도와 작은 설치 크기를 목표로 한다.
- 데이터 저장 및 조회는 로컬에서 빠르게 처리되어야 한다.

### 2. 로컬 우선 구조
- 앱의 원본 데이터는 항상 사용자 PC 내부 저장소에 존재해야 한다.
- 네트워크 연결이 없어도 핵심 기능은 동작해야 한다.
- 외부 동기화 실패가 로컬 데이터 손실로 이어지면 안 된다. 로컬 우선 소프트웨어는 기기 내부 데이터를 기준으로 동작하고 외부 동기화는 부가 계층으로 두는 설계가 일반적이다[cite:69][cite:80].

### 3. 사용성
- 구글 계정 연동은 선택적으로 제공되어야 하며 기본 사용 흐름을 방해하면 안 된다.
- 사용자는 설치 후 즉시 달력 조회와 메모 저장을 시작할 수 있어야 한다.
- 날짜 선택, 메모 작성, 저장, 추출 흐름은 최소 클릭 수로 이루어져야 한다.

### 4. 안정성
- 앱 비정상 종료 후에도 저장된 메모는 복구 가능해야 한다.
- 로컬 저장 구조는 손상 가능성이 낮고 백업이 쉬워야 한다.
- Google Calendar 연동 실패 시에도 앱은 정상 동작해야 하며, 실패 사실만 사용자에게 안내해야 한다.

### 5. 보안 및 개인정보
- 메모 데이터는 기본적으로 외부 서버에 저장하지 않는다.
- Google 연동 시에도 필요한 최소 권한만 요청해야 한다. Google은 애플리케이션이 필요한 범위의 OAuth scope만 선택하도록 안내한다[cite:58][cite:54].
- 인증 토큰은 로컬에 안전하게 저장되어야 하며, 로그아웃 또는 연결 해제 시 제거 가능해야 한다.

## 데이터 저장

### 1. 저장 원칙
본 애플리케이션의 메모 및 설정 데이터는 사용자 PC 내부에 저장한다. 외부 연동 여부와 관계없이 로컬 저장소가 단일 기준 데이터(source of truth)가 되어야 한다[cite:69][cite:80].

### 2. 저장 방식
MVP 단계에서는 SQLite를 기본 저장소로 채택하는 것을 권장한다. SQLite는 파일 기반 구조로 가볍고 배포가 쉬우며, 로컬 데스크톱 애플리케이션에서 데이터 일관성을 유지하기에 적합하다.

### 3. 저장 대상
저장 대상 데이터는 다음과 같이 구분한다.

| 구분 | 설명 |
|------|------|
| 사용자 메모 | 날짜별 제목/내용/생성·수정 정보 |
| 앱 설정 | 창 위치, 마지막 표시 월, 테마, 연동 상태 |
| 동기화 메타데이터 | Google event id, 마지막 동기화 시각, 동기화 상태 |
| 인증 정보 | Google OAuth 토큰 또는 연결 상태 정보 |

### 4. 예시 데이터 모델

#### Memo
- memo_id
- target_date
- title
- content
- created_at
- updated_at
- is_calendar_event
- sync_enabled

#### GoogleSyncMap
- memo_id
- google_event_id
- sync_status
- last_synced_at
- last_error_message

#### AppSetting
- setting_key
- setting_value

### 5. 추출 구조
앱은 로컬 저장 데이터를 외부 전달용 포맷으로 변환할 수 있어야 한다.
- JSON: 내부 데이터 백업 및 재활용용
- CSV: 목록형 데이터 검토 및 엑셀 호환용
- ICS: 외부 캘린더 반영용 표준 일정 파일

iCalendar는 일정 및 캘린더 정보를 교환하기 위한 표준이며, Google Calendar를 포함한 다양한 일정 서비스와의 상호 운용성 확보에 적합하다[cite:38][cite:44].

## Google Calendar 선택 연동 정책

### 1. 기본 정책
Google Calendar 연동은 기본 비활성화 상태로 제공한다. 사용자가 명시적으로 연결을 선택하기 전까지 앱은 로그인이나 외부 권한 요청을 수행하지 않는다[cite:58].

### 2. 사용자 경험 원칙
- 사용자는 API Console, OAuth 설정, API 키 발급 같은 개발자 작업을 수행하지 않는다.
- 사용자는 앱 내 “Google Calendar 연결” 기능을 통해 로그인과 동의만 수행한다.
- 사용자는 원할 때 연결을 해제할 수 있어야 한다.

Google Calendar API 접근은 OAuth 2.0 승인 절차를 필요로 하며, 앱은 필요한 Calendar scope를 선언해야 한다[cite:58][cite:54].

### 3. 연동 활성화 흐름
1. 사용자가 “Google Calendar 연결”을 선택한다.
2. 시스템 기본 브라우저에서 Google 로그인 페이지를 연다.
3. 사용자는 계정을 선택하고 권한 동의를 완료한다.
4. 애플리케이션은 승인 토큰을 저장하고 연동 상태를 활성화한다.
5. 이후 사용자가 선택한 메모 또는 일정만 Google Calendar에 반영한다.

### 4. 최소 권한 원칙
Google Calendar 연동 시에는 필요한 최소 scope만 요청해야 한다. Google은 scope를 기능 요구에 맞게 최소화할 것을 권장하며, 읽기 전용과 읽기/쓰기 범위를 구분해 제공한다[cite:58][cite:54].

### 5. 동기화 범위 원칙
- 로컬 메모 전체를 자동 업로드하지 않는다.
- 사용자가 일정으로 지정한 항목만 외부 이벤트로 변환한다.
- 사용자 연결 해제 후에도 로컬 메모는 유지된다.
- 동기화 실패 항목은 재시도 가능 상태로 남겨야 한다.

### 6. 연동 실패 처리
- 로그인 실패, 권한 거부, 토큰 만료, 네트워크 오류를 구분해 처리해야 한다.
- 실패 시 로컬 기능은 계속 사용할 수 있어야 한다.
- 사용자에게는 실패 원인과 재시도 방법만 간단히 안내한다.

## MVP 범위

### 포함 범위
MVP는 다음 기능에 집중한다.
- 현재 월 달력 표시
- 날짜 선택
- 날짜별 메모 CRUD
- 로컬 SQLite 저장
- JSON 추출
- 기본적인 ICS 추출
- Google Calendar 선택 연동 구조 설계
- 사용자가 선택한 일정의 Google Calendar 반영

### 제외 범위
초기 MVP에서는 다음 기능을 제외한다.
- 반복 일정
- 다중 캘린더 계정 동시 연결
- 푸시 알림 및 리마인더
- 팀 공유 기능
- 클라우드 백업 서버
- Outlook, Apple Calendar 직접 API 연동
- 고급 검색 및 태그 체계

### MVP 목표
MVP의 목표는 “구글 연동이 없어도 독립적으로 쓸 수 있는 로컬 캘린더 메모 위젯”을 완성하는 것이다. 이후 확장 단계에서 Google Calendar 동기화 고도화, ICS 가져오기, 반복 일정, 알림 기능을 추가하는 방향이 적절하다[cite:69][cite:58][cite:38].
